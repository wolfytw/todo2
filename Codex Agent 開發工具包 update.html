為什麼不再叫「五層堆疊」

原圖把不同維度排成固定上下游。更新後改成「核心＋介面＋能力軌道＋執行邊界」，更能表達元件如何交叉組合。

AGENTS.md是上下文／指令來源，不是記憶體系統。
Plugin ≠ Extension前者是發布包；後者是核心內部貢獻者介面。
Hooks ≠ 一個流程階段它們橫跨 session 與工具生命週期。
MCP ≠ Plugin 附屬品可由設定或 Plugin 宣告，最終接到工具面。

Agent 核心

codex-rs/core · protocol

負責 agent loop、工具呼叫、事件與狀態協調；各種介面共用這個核心。

輸入
Prompt、Context、Tool results
輸出
Events、Actions、Final response

Skills

codex-rs/skills

目錄式能力包，以描述做發現，內容提供可重複使用的專業流程與參考資料。

核心檔
SKILL.md
觸發
明確 mention／模型依描述選用

Plugins

codex-rs/plugin · core-plugins

可解析、安裝與發布的 bundle；manifest 聚合多種貢獻物，而非只是一段執行程式。

可包含
Skills、MCP、Apps、Hooks
來源
本地、registry、遠端

Extensions

codex-rs/ext

核心的貢獻者架構；讓內建能力掛載 Context、Tool、Output、Request、Turn 或 Runtime。

例子
memories、guardian、skills、connectors
定位
內部擴充 API

Hooks / Rules

codex-rs/hooks · execpolicy

事件驅動的攔截與政策層，在 session 或工具呼叫前後執行，並與審批機制協作。

事件
session、prompt、tool、stop、compact
用途
檢查、記錄、阻擋、轉接

MCP / Connectors

codex-mcp · rmcp-client · ext/connectors

將外部服務或工具掛入 Agent 可用的能力集合；來源可由全域設定或 Plugin 提供。

角色
工具／服務整合
邊界
獨立連線、權限與設定

Subagents

delegated execution

由主 Agent 委派的工作單元，使用隔離的上下文與工具範圍完成專責或平行任務。

優點
隔離、平行、專責
回傳
結果匯入主 Agent 決策

Tools / Sandbox

shell-command · apply-patch · *-sandbox

真正讀寫檔案、執行命令與呼叫外部工具的地方；執行受到 policy、approval 與 sandbox 管制。

治理
規則與使用者核准
隔離
平台特定 sandbox
